# 三感问卷制作流程与验证关卡（SOP）

> 相关文件：
> [`three-senses-scale.md`](./three-senses-scale.md) 编制方案与条目池（**唯一权威来源**）·
> [`tss-scoring.js`](./tss-scoring.js) 登记与参考计分实现 ·
> [`tss-30-form.html`](./tss-30-form.html) 施测卷 ·
> [`verify.js`](./verify.js) 交付物核验套件（`npm run verify:scale`）

本文档回答两个问题：**这份问卷是怎么一步步做出来的**，以及**每一步凭什么说它做对了**。
后者是重点——流程只要没有可核验的关卡，就只是一份好看的计划。

## 三层可验证性

把"可验证"拆成三层，每层各有自己的手段和失效方式。混在一起谈，就会出现
"跑了一堆统计但没人能复算"或者"文件互相矛盾却没人发现"这类问题。

| 层 | 验的是什么 | 手段 | 什么时候跑 |
|---|---|---|---|
| **第 1 层：机器可验证** | 交付物之间不漂移、对外承诺不落空 | `verify.js`（48 项，见 §「机器检查清单」） | 每次改动后、每次提交前 |
| **第 2 层：数据可验证** | 心理测量指标是否达到预先写定的数字 | 预注册的关卡判据 + 事先冻结的分析代码 | 每个数据阶段结束时 |
| **第 3 层：独立可验证** | 别人能不能不靠我们复算一遍 | 条目全文 + 计分实现 + 合成数据黄金测试随包公开 | 发布时 |

第 1 层是本项目相对常规量表编制多出来的一层。它便宜、可重复、能抓住人眼最容易漏的那类错误：
**条目改了但计分脚本没跟、卷面题号和登记错位、承诺"不上传"但代码里留了一个请求。**

## 阶段流程

每个阶段的格式一致：**目的 → 输入 → 动作 → 产出 → 关卡（数字）→ 不通过怎么办 → 留痕**。
关卡一律在开工前写定，不允许看到数据后再调。

### 阶段 0 · 立项与否证条件前置

- **目的**：先把"什么情况下这个量表不该存在"写清楚，再开始做。
- **动作**：界定三个构念与它们的结构关系；审计既有量表（BHS / MLQ / GSES / PHQ-9）的覆盖范围；写否证条件。
- **产出**：构念界定书；否证条件清单。
- **关卡**：三条否证条件**必须是数字**——
  ① 各分量表双因子 ωHS ≥ .30；② 控制 PHQ-9 + BHS 后 ΔR² ≥ .03；③ 操纵-分量表矩阵对角 ≥ 0.6 SD 且非对角 < 0.25 SD。
  写不出数字 → 不进入阶段 1。
- **留痕**：立项文档打 git tag `scale-v0.0-charter`。

### 阶段 1 · 构念界定与条目撰写

- **输入**：理论框架（动机链三处断裂）；目标人群的**质性访谈 n = 25**（半结构，覆盖临床与非临床）。
- **动作**
  1. 访谈转录 → 开放编码 → 归入 9 个侧面，记录**编码覆盖不到的表述**（它们提示侧面清单不完整）；
  2. 每侧面撰写 5 题（条目池 53 题，含 PD 模块 8 题）；
  3. 逐条过撰写规则（单一命题 / 无嵌套否定 / ≤ 20 字 / 不含躯体症状 / 不写因果 / 无自杀内容）；
  4. 与既有量表逐条做**语义重叠审计**，实质同义者删除。
- **产出**：条目池 TSS-53（文档附录 A 为唯一权威来源）；重叠审计表。
- **关卡**
  - 机器：`verify.js` A 组 7 项全过（题号连续、侧面各 5 题、每侧面 ≥ 1 反向题、文本规则）；
  - 人工：两名独立编码者把条目盲分到 9 个侧面，**归属一致性 κ ≥ .80**；
  - 覆盖：访谈中出现但 9 个侧面都装不下的表述 ≤ 5%，否则侧面清单需要修订。
- **不通过怎么办**：κ < .80 说明侧面之间界限不清——优先改**侧面定义**，其次改条目，不要靠删条目凑一致性。
- **留痕**：条目池 CSV + 版本号 + git tag；任何条目改动记录 who / when / why / before / after。

> **本阶段当前的缺口**：质性访谈与双编码者 κ 都没做。现有条目池是理论演绎的产物，
> 属于"可以拿去评审的草案"，不是"经过来源验证的条目池"。

### 阶段 2 · 专家内容效度

- **输入**：条目池 TSS-53；侧面定义书。
- **动作**：9 名专家（认知心理 / 临床 / 心理测量各 3）独立完成两项任务——
  1. **相关性评定**：每条目对目标侧面的相关性 1–4 分；
  2. **盲分类**：把条目打乱后分到 9 个侧面（不告诉他们原归属）。
- **产出**：I-CVI / S-CVI / CVR 表；盲分类混淆矩阵。
- **关卡**
  - 条目层 **I-CVI ≥ .78**；量表层 **S-CVI/Ave ≥ .90**；Lawshe **CVR** 达 9 人对应临界值；
  - **盲分类命中率 ≥ 80%**——这一项比 I-CVI 更关键：它在条目层面直接检验"三感可分"，
    如果专家都分不清一条目是无助还是绝望，被试更分不清；
  - **已登记的撰写规则例外逐条复核**（目前 1 条：#46 的「免得」）。
- **不通过怎么办**：命中率低的条目看混淆去向——若系统性错分到相邻侧面，改条目；
  若整个侧面被打散，改侧面定义并回到阶段 1。
- **留痕**：专家原始评分表 + 计算脚本（可复算）；改写前后对照。

### 阶段 3 · 认知访谈

- **输入**：阶段 2 定稿的条目；卷面（用于观察真实作答行为）。
- **动作**：n = 12，分 3 轮各 4 人。出声思考 + 事后追问（这道题你是怎么理解的 / 你想到了什么 / "过去两周"你是怎么算的）。
- **重点观察**：反向题是否引起卡顿；"一半以上的日子"这类频率锚点是否被稳定理解；
  同一条目是否被不同人读成不同意思。
- **关卡**：同一条目在**一轮内 ≥ 2 人误解 → 必须改写**并进入下一轮；
  **连续两轮无新问题 → 条目定稿**。三轮后仍有问题条目 → 删除。
- **留痕**：逐题问题日志；每轮的改写记录；访谈录音编码表。

### 阶段 4 · 卷面实现与技术验收

- **输入**：定稿条目；计分规则；伦理条款（方案 §9）。
- **动作**：实现 `tss-scoring.js`（参考实现）与 `tss-30-form.html`（施测卷）；写 `verify.js`。
- **关卡（机器）**：`npm run verify:scale` **48 项全过**，其中不可让步的三类：
  - **跨文件一致性**：卷面题干与条目池**逐字**一致；卷面呈现顺序等于登记的 `PRESENTATION_ORDER`；
  - **计分等价性**：卷面内实现与参考实现在 500 组随机作答 + 缺失边界 + 反向方向 + PD 不计入总分上完全一致；
  - **对外承诺**：无 fetch/XHR/WebSocket、无 localStorage/cookie、无第三方脚本、卷面无自杀条目、不呈现切分点分档。
- **关卡（人工验收，机器验不了的）**：键盘可完整作答；屏幕阅读器能读出题干与选项；
  400px 宽度无横向滚动；深浅两主题均可读；打印为 PDF 后仍是一份可用纸质卷。
- **不通过怎么办**：`verify.js` 失败即视为交付物已漂移，**先修再做任何别的事**。
- **留痕**：`verify.js` 输出存档；人工验收清单签字。

### 阶段 5 · 预注册与分析代码冻结

- **动作**：登记假设、关卡数字、样本量、排除标准、否证条件；**用合成数据把全部分析脚本跑通**。
- **关卡**：预注册获得时间戳；分析脚本在合成数据上产出**完整**报告（不是能跑就行，是每张表每个数都填满）。
- **不通过怎么办**：脚本在合成数据上跑不完 → 说明分析计划有洞，这时候补洞是免费的，见到真数据再补就是 p-hacking 的入口。
- **留痕**：预注册链接 + 冻结代码的 commit hash，两者互指。

### 阶段 6 · 预试（n = 60）

- **目的**：校准而非检验。
- **产出**：作答时长分布；单题缺失率；天花板/地板反应率；**筛查三指标的经验分布**。
- **关卡**：中位完成时间 ≤ 8 分钟；单题缺失率 ≤ 3%；无条目天花板反应 > 20%。
- **直接输出**：用 longString 的 99 百分位与 IRV 的 1 百分位**替换** `CARELESS_DEFAULTS` 里的默认值——
  默认值只是个保守起点，真实阈值必须来自样本。
- **留痕**：校准后的阈值与其经验分布图，写入方案 §5。

### 阶段 7 · 样本 1（N = 600）条目分析与定版

- **动作**：描述统计 → 校正后条目-总分相关 → 并行分析/EFA → GRM（分级反应模型）→ DIF。
- **关卡**：|偏度| ≤ 2；天花板/地板 < 20%；条目-总分相关 ≥ .40；EFA 主负荷 ≥ .50 且交叉负荷 ≤ .32；
  GRM 区分度 a ≥ 1.0；性别/年龄 DIF 不可忽略者删除。
- **产出**：**TSS-30 定版**。
- **铁律**：定版锁定后，**样本 2 不得再改条目**。改了就必须重新收样本 2。
- **留痕**：定版 git tag；条目池版本号递增；重跑 `verify.js`。

### 阶段 8 · 样本 2（N = 600）独立结构确认

- **动作**：CFA（WLSMV）→ 单因子 / 三因子相关 / 二阶 / **双因子** / ESEM 竞争模型 → 测量等值性。
- **关卡**：CFI、TLI ≥ .95；RMSEA ≤ .06；SRMR ≤ .08；等值性 ΔCFI ≤ .01；
  **生死线：各分量表 ωHS ≥ .30**（用 `bifactorIndices()` 算，判定用 `verdict()`）。
- **注意**：PUC 只报告不设门槛——它由维度数 × 每维题数决定，3×9 恒为 .692，与数据无关。
- **不通过怎么办**：按方案 §6.2 的处置顺序（补足侧面覆盖 → 该维降为总分侧面 → 放弃三维结构）。
  **不允许**靠加载荷或删条目把 ωHS 调过阈值。
- **留痕**：模型语法、全部拟合指标、双因子指标表。

### 阶段 9 · 信度与效度

- **动作**：ω / 分量表 ωS；2 周重测 ICC；状态-特质方差分解；聚合与区分效度；
  **增量效度**（控制 PHQ-9 + BHS 的分层回归）；临床已知组。
- **关卡**：特质版重测 ICC ≥ .70；状态版状态方差占比 ≥ 40%；社会赞许性 |r| ≤ .20；
  每个分量表与自己"对口"的外部量表相关最高；**增量 ΔR² ≥ .03（p < .01）**；临床 vs 对照 d ≥ 0.8。
- **不通过怎么办**：增量效度不过 → **停止**，不作为新量表发表。这是阶段 0 就写定的否证条件。

### 阶段 10 · 实验效度（本量表独有）

- **动作**：三种诱导（无助 / 无意义 / 绝望）× TSS-S12 三个分量表 → 3×3 操纵-分量表矩阵；
  与实验方案的 Study 0B 共用 180 名被试。
- **关卡**：**对角 ≥ 0.6 SD，非对角 < 0.25 SD**。
- **附带**：PD 分数应预测 Study 2 中三感的上升斜率；不预测则 PD 退为描述性条目。
- **伦理**：本阶段含负性情绪诱导，须按实验方案 §10 执行筛查、停止规则、去欺骗与情绪恢复。

### 阶段 11 · 常模、切分点与发布

- **动作**：分版本建常模（TSS-30 / TSS-12 / TSS-S12，**不跨版本换算**）；
  以临床诊断为标准做 ROC。
- **关卡**：报告 AUC、敏感性、特异性、Youden 指数，并**明确写出 PPV 依赖所在人群基础率**；
  正文明确声明本量表不是诊断工具。
- **发布包**（第 3 层可验证性）：条目全文 + 计分实现 + `verify.js` + 合成数据黄金测试 + 分析脚本 + 专家评分原始表。
  **不公开条目的量表无法被复制检验**，等于没有第 3 层。

## 机器检查清单（`npm run verify:scale`）

48 项，六组。它读三份文件并让它们互相对账，其中 **C 组是把卷面页面里那份计分实现
直接取出来执行**，而不是在检查脚本里重写一遍——重写只能证明"我写了两次"。

| 组 | 项数 | 验什么 | 举两个例子 |
|---|---|---|---|
| **A** 条目池不变量 | 7 | 条目池自身完整 | 题号 1–53 连续；9 个侧面各 5 题；条目不含躯体症状词 |
| **B** 跨文件一致性 | 13 | 三份文件对账 | 卷面题干与条目池**逐字**一致；卷面呈现顺序 = 登记的 `PRESENTATION_ORDER` |
| **C** 计分等价性 | 7 | 两份实现同解 | 500 组随机作答得分完全一致；缺失 2/9 计分、3/9 不计分的边界 |
| **D** 对外承诺 | 7 | 承诺没落空 | 无 localStorage/fetch；卷面无自杀条目；不呈现严重程度分档 |
| **E** 卷面可用性 | 9 | 静态可检的可用性 | 所有颜色 token 在 bare `:root` 有定义；每根条形直接标数值 |
| **F** 诊断工具自检 | 5 | 工具本身没算错 | 强一般因子情景须判为"本质单维、三维失败" |

### 它已经抓到过的四个真问题

这不是假设，是实际发生的——每一个都属于"肉眼几乎不可能稳定发现"的类型：

1. **侧面失衡**：无助维登记的 9 题实为 4+2+3 题，而文档声称 3 侧面 × 3 题。
2. **PUC 当成硬门槛**：`ωH ≥ .80 且 ECV ≥ .70 且 PUC ≥ .70` 里，PUC 只由维度数 × 题数决定，
   3×9 恒为 .692，永远达不到 .70——照抄这条判据会让单维结论永远无法触发。
3. **长串指标算错了顺序**：参考实现按题库编号排序计算"连续多少题选同一个数字"，
   但卷面是打乱呈现的，被试的实际作答顺序完全不同。已改为登记 `PRESENTATION_ORDER`。
4. **条目把因果链写进了题干**：#48「我提前认定做不到，**所以**不去做」、
   #51「我不去尝试，**是因为**我已经知道结果了」违反自订的撰写规则。已改写。
   同时暴露出检查规则自身的一个误报（成语「讲不出个所以然」被当成因果连词），也已修掉。

第 2、3 两项是判据与实现层面的错误：它们不会让任何程序崩溃，只会让结论悄悄错掉。

## 留痕与审计规则

1. **唯一权威来源**：条目文本只有一处定义——`three-senses-scale.md` 附录 A。
   计分登记与卷面都是它的下游，由 `verify.js` 强制对账。
2. **版本号**：`scale-v<主>.<次>`。条目增删改 → 主版本递增；仅措辞微调 → 次版本递增。
   每次递增打 git tag，并在提交信息里写清改了哪些题号、为什么。
3. **变更日志**：任何条目改动必须记录 who / when / why / before / after。
   "阶段 3 认知访谈发现 3 人把 #22 读成时间管理问题"是合格理由；"读起来更顺"不是。
4. **冻结点**：阶段 5 冻结分析代码，阶段 7 冻结条目。冻结后的改动必须有新的 tag 与理由，
   并说明是否需要重新收数据。
5. **检查前置**：`verify.js` 失败时不提交。它就是这套流程的第 1 层，绕过它等于没有第 1 层。

## 常见的流程失效模式（反面清单）

| 失效 | 长什么样 | 本流程的拦法 |
|---|---|---|
| 指标当目标 | 为了让 α 好看而删掉内容上必要的条目 | 阶段 7 的删条目须记录理由；阶段 8 明令不许调 ωHS |
| 看到数据再定关卡 | "RMSEA .08 也算可接受吧" | 阶段 5 预注册 + 冻结分析代码 |
| 交付物悄悄漂移 | 改了条目但计分脚本没跟 | `verify.js` B/C 组 |
| 承诺落空 | 卷头写"不保存"，代码里留了 localStorage | `verify.js` D 组 |
| 规则有洞 | 撰写规则写了"不写因果"，却有条目违反 | `verify.js` A 组 + 例外登记（例外要被看见，不是漏洞） |
| 判据照抄 | 抄来的门槛在本结构下永远不可能成立 | 阶段 8 的 PUC 说明；F 组自检 |
| 无法复算 | 论文发表但条目与计分不公开 | 阶段 11 的发布包清单 |
| 用未验证的量表下结论 | 拿 v0.1 卷面的分数说"这个人绝望水平高" | 卷面不呈现切分点与分档（D 组强制） |
